🔬 Key Technical Discoveries During Port & Testing

O17 Ticket Header Buttons — Silent No-ops in Headless

  • type="action" server-action buttons fire, produce no JS error, open no dialog, leave record unchanged in Playwright headless mode
  • type="object" wizard-opening buttons (e.g. Plan Intervention) also do nothing
  • Fix: RPC ir.actions.server.run([id], {context}) for server actions; ORM helper scripts for wizard flows

@api.onchange Does Not Run on ORM create()

  • Only the write() override fires _sync_ticket_type_flags and _sync_serial_fields
  • Pattern: create({base}) then .write({ticket_type_id, x_studio_serial_no})
  • Without this, x_studio_rug_repair, x_studio_rug_confirmed, x_studio_sn_updated stay False

execSync Kills Playwright Browser Connection

  • Blocking docker exec calls freeze the Node event loop for several seconds
  • Playwright loses its browser WebSocket → "Target page closed"
  • Fix: execAsync = promisify(exec) and await all docker calls

O17 SPA Router — Same-Hash Page Navigation Skip

  • page.goto(same_url) is a no-op when hash is identical — OWL skips re-render
  • page.reload() leaves form dirty (onchange virtual state conflicts with DB)
  • Fix: cache-busting ?_t=<timestamp> query param forces full HTTP reload

OWL Form Dirty State After Assign-to-Me Auto-Save

  • After auto-save, Playwright fill() updates DOM but OWL's dirty tracker doesn't register it
  • Clicking Save submits a "clean" record — m2o fields silently dropped
  • Fix: bypass UI ticket creation entirely, use ORM helper

SA1009 (RUG Return) — Full ORM Replication

  • Server action on stock.return.picking model
  • Creates incoming receipt with x_studio_helpdesk_ticket_id, move + move.line (picked=True), links to ticket, validates via _action_done()
  • Replicated as create_rug_receipt.py

invoice.x_studio_rug_confirmed Chain

  • account.move.x_studio_rug_confirmed ← related x_studio_sale_id.x_studio_rug_confirmed
  • sale.order.x_studio_rug_confirmed ← related task_id.helpdesk_ticket_id.x_studio_rug_confirmed
  • SO.task_id is NOT set automatically by industry_fsm_sale — must be set manually after SO creation

x_studio_repair_reason — Many2many Pitfall

  • Field is Many2many, not Many2one
  • Must use [(6, 0, [id])] command syntax in ORM writes
  • Passing a plain integer raises ValueError: Wrong value for x_studio_repair_reason
⚠️ Open Issues & Next Steps
  • 🔴 BLOCKER — SO.task_id not set after FSM task product add

    When industry_fsm_sale auto-creates the SO from product addition on the FSM task, sale.order.task_id is not populated. This breaks the x_studio_rug_confirmed related-field chain all the way to the invoice. Fix: after SO creation in STEP D2, set SO.task_id = fsmTaskId via ORM and re-trigger the computed field.

  • 🟡 PENDING — STEPs F, G, H, I not yet reached

    Mark as Done (STEP F), Send/Receive at Sales Centre (STEPs G/H, wired with RPC 1014/1015), and Dispatch → Handed Over (STEP I) have not been reached in testing yet due to the STEP E blocker. STEPs G/H/I are already coded with RPC/ORM patterns.

  • 🟡 PENDING — "Update RUG Account" button on invoice (STEP E-inv)

    The action_update_rug_account button on account.move is also likely a silent no-op in headless Playwright. May need RPC call account.move.action_update_rug_account([invoiceId]) instead of button click — to be verified once the SO.task_id blocker is resolved.

  • 🔵 NOTE — "Approve RUG" button not visible on SO

    The SO's "Approve RUG" button was not visible in the last test run (x_studio_rug_approved=false). Button visibility is gated by x_studio_rug_confirmed=True on the SO — will resolve once SO.task_id is fixed.

  • 🔵 NOTE — CLAUDE.md needs post-green update

    The /opt/odoo15/CLAUDE.md "Known Gotchas" and "Active Work" sections need updating with: ORM-create ticket pattern, server-action-button no-op + RPC workaround, execAsync requirement, gotoTicket cache-bust approach, SO.task_id issue.
