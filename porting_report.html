🔬 Key Technical Discoveries — Port & Testing

O17 Header Buttons — Silent No-ops in Headless Playwright

  • type="action" server-action buttons and type="object" model-method buttons fire no JS error, open no dialog, and leave the record unchanged in headless mode
  • Fix: RPC ir.actions.server.run([id], {context}) for server actions; direct model method RPC for type="object" buttons
  • Affects: Return, Send/Receive at Factory, Send/Receive at Sales Centre, Plan Intervention, Approve RUG, Confirm SO, Mark as Done, Update RUG Account

@api.onchange Does NOT Run on ORM create()

  • Only the write() override fires _sync_ticket_type_flags and _sync_serial_fields
  • Pattern: create({base fields}) then .write({ticket_type_id, x_studio_serial_no})
  • Without this, all x_studio_rug_* flags stay False after ticket creation

SO.task_id Not Set by industry_fsm_sale

  • When industry_fsm_sale auto-creates an SO from FSM task product addition, SO.task_id is NOT set
  • Breaks the entire chain: SO.x_studio_rug_confirmed → invoice.x_studio_rug_confirmed → "Update RUG Account" button visibility
  • Fix: manually set SO.task_id = fsmTaskId via ORM after SO creation

SO Must Be Locked Before Update RUG Account

  • Automation rule "RR - Validate RUG in Customer Invoice" fires on x_studio_rug_acc_updated=True and checks SO.locked=True
  • In O17, locked is NOT automatic after delivery — must call action_lock() manually
  • Fix order: validate delivery → action_lock() → action_update_rug_account()

execSync Kills Playwright Browser Connection

  • Blocking docker exec calls freeze the Node event loop for several seconds
  • Playwright loses its browser WebSocket → "Target page, context or browser has been closed"
  • Fix: execAsync = promisify(exec) — all docker calls are awaited asynchronously

O17 SPA Router — Cache-Busting Required for Navigation

  • Same-hash page.goto() is a no-op — OWL skips re-render, leaving stale button set visible
  • page.reload() leaves form dirty (onchange virtual state conflicts with DB)
  • Fix: ?_t=<timestamp> query param on every navigation forces full HTTP reload

SO Delivery Move Lines — picked=False by Default

  • When an SO delivery is created, Odoo pre-populates move lines with picked=False
  • Calling _action_done() without setting picked=True leaves the picking in assigned state
  • Fix: existing_lines.write({'picked': True}) before pick._action_done()

SA1009 (RUG Return) — Full ORM Replication

  • Server action on stock.return.picking — creates incoming receipt with x_studio_helpdesk_ticket_id, move + move.line (picked=True), links to ticket, validates via _action_done()
  • Replicated as create_rug_receipt.py — works reliably where the UI Return button is a no-op

action_create_payments() Must Be Used (Not _create_payments)

  • The module's ported AccountPaymentRegister.action_create_payments() override calls _advance_ticket_stage(ticket, task, 'Advance Received', ...) setting task.x_studio_valid_invoiced_so=True
  • Calling the private _create_payments() directly bypasses this hook — stage stays at "Estimation Approval Received" and "Send to Sales Centre" remains hidden
  • Non-Warranty flow fix: ORM payment script uses wizard.action_create_payments(); retrieve payment via account.payment.search([('reconciled_invoice_ids', 'in', [invoice.id])])

Non-Stored Compute with Write Side-Effects Causes OWL Error

  • _compute_x_studio_task_status has no @api.depends — it only runs when x_studio_task_status is explicitly read
  • When first triggered via web_read (form load), the compute writes stage_id='Repair Completed' and flags mid-render — this triggers an OWL error dialog, hiding all statusbar buttons
  • Fix: after action_fsm_validate in STEP K, immediately read x_studio_task_status via RPC so the compute fires (and commits its writes) before gotoTicket loads the form
  • Pattern: for any store=False compute with DB write side-effects, force a read before navigating to the form

Non-Warranty Flow — No RUG Cost Swap

  • sale_order._apply_rug_price_swap and sale_order_line.create swap to standard_price ONLY when x_studio_rug_confirmed=True AND x_studio_is_repair_order=True
  • Non-warranty: rug_confirmed=False, so the SO line keeps the list price throughout — customer pays full selling price
  • RUG approval buttons (Request/Approve RUG) are correctly absent on the non-warranty SO

📝 Notes
  • ✅ Non-Warranty (With Serial No) E2E Green — 19 June 2026

    The Non-Warranty (With Serial No) Factory Repair flow passes all 69 checks end-to-end on the first run. Key differences from the Without-Serial flow: (1) customer's pre-existing serial (stock.lot) is set at ticket creation via write(), which auto-triggers _sync_serial_fields() setting x_studio_sn_updated=True and x_studio_pick_id to the original delivery — no "Create Repair Serial" SA needed; (2) receipt uses the original outgoing delivery as reference; (3) "Update Serial" button correctly hidden since sn_updated=True already. New helpers: setup_withserial_master_data.py, create_withserial_ticket.py, create_withserial_receipt.py.

  • ✅ Non-Warranty (Without Serial No) E2E Green — 19 June 2026

    The Non-Warranty Factory Repair flow passes all 68 checks end-to-end: ticket creation → create repair serial → return receipt → factory transit → FSM task + diagnosis + products (list price, no RUG cost-swap) → invoice → payment (stage advance hook) → delivery → mark done → sales centre transit → dispatch → Handed Over to Customer.

  • ✅ RUG Factory Repair E2E Green — 18 June 2026

    The RUG Factory Repair flow passes all 58 checks end-to-end: ticket creation → return receipt → factory transit → FSM task + diagnosis + products → SO approval → invoice → delivery → RUG account update → mark done → sales centre transit → dispatch → Handed Over to Customer. No blockers remain.

  • 🔵 "Confirm" button on SO — correctly handled

    The SO "Confirm" button is not visible because action_approve_rug auto-confirms the SO (sets state=sale directly). The test detects state=sale and skips the redundant confirm RPC. This is correct behaviour matching the O15 flow.

  • 🔵 Centre Repair flow (rug_flow_phase2_test.js)

    The Centre Repair (non-factory) flow test stands at 24/27 checks. The remaining 3 are lower priority and were not the focus of this porting sprint. The Factory Repair flow was the primary deliverable.

  • 🟡 Headless Playwright — all model-method buttons require RPC

    Any type="object" or type="action" button on Odoo 17 ticket/SO/invoice/task forms is a silent no-op when clicked in headless Playwright. Future tests must use rpc(page, model, method, [ids], kwargs) for all such buttons. This is an Odoo 17 headless environment characteristic, not a bug in the module.
